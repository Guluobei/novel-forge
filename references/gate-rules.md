# 门禁规则详解（G01-G12）

门禁继承 cn-novel-craft 已验证的 10 步量化门禁并工程化为 12 条确定性规则。
全部本地机检，无 AI 参与，结果 100% 可复现。

级别语义：

- **error**：结构性问题，章节不通过（check 退出码 1），每单位扣 5 分
- **warn**：AI 味风险点，每单位扣 2 分；`--strict` 时也判不通过
- **info**：仅提示，不扣分

评分 = max(0, 100 - error单位×5 - warn单位×2)。单位 = 超出限额的处数（零容忍规则 = 每处 1 单位）。

## 规则清单

| ID | 名称 | 级别 | 默认阈值 | 检查内容与修改指引 |
|---|---|---|---|---|
| G01 | 字数下限 | error | ≥3000 字 | 去空白字符数（含标点）。不足时扩写方向：心理独白、环境渲染、动作细节、配角反应——不要注水重复 |
| G02 | 破折号密度 | error | ≤12 处/章 | 统计「——」。解释改冒号、转折改句号、补充改分号、强调改动作打断 |
| G03 | ban 词 | error | 0 容忍 | 词表见下；命中即删除或改写。ban 词是 AI 味最强信号 |
| G04 | warn 词 | warn | ≤3 次/章 | 次数超限则本类场景写法单一，换其他手法 |
| G05 | limit 词限量 | error | 每词各自 max | 高频套路短语限量（如「嘴角勾起」≤2） |
| G06 | 钩子登记 | warn | 必填 | frontmatter 的 hook_type 必须属于 8 类：危机/悬疑/反转/信息/情感/时间/选择/生存 |
| G07 | 裸对话标签 | warn | ≤30% | 「我/你/他/她/它 + 说/道/问道…」占全部复合标签的比例。改用动作标签：`他把杯子放到桌上。` |
| G08 | 章末收束 | error | — | 末句禁反问（？）、禁感叹（！）、禁「第X章完/（完）」平收。以陈述、动作或画面收尾 |
| G09 | 情绪命名 | warn | ≤2 次/章 | 「感到/觉得/感觉到」计数。改写为行为外化：`他感到愤怒` → `他没说话，把杯子放得很响` |
| G10 | 长短句交替 | info | CV ≥0.25 | 按 。！？切句计算句长变异系数，过低提示拆长句、并短句 |
| G11 | 钩子多样性 | warn | 连续 3 章不同型 | 依 frontmatter 历史检查；连续同型时换钩子类型 |
| G12 | 段首重复 | info | — | 连续 ≥3 段以相同 2 字开头则提示，变换段落开头方式 |

## 内置词表（assets/lexicon.default.json）

- **ban（零容忍）**：不禁、与此同时、内心深处、缓缓说道、命运的齿轮、宿命感、忍不住、下意识地、不由自主地、众所周知、不言而喻、然而、一股莫名；正则：`一股.{0,6}涌上心头`、`空气[中里]弥漫着`
- **warn（≤3 次）**：深吸一口气、时间来到了、另一边、仿佛、似乎、片刻后、闻言
- **limit（每词限量）**：嘴角勾起×2、眸中闪过×2、眼底闪过×2、心跳加速×2、咬了咬牙×2、眯起眼睛×2

## 项目级词表覆盖（book.json）

```json
"gate": {
  "lexicon_override": {
    "ban":   {"add": ["瞳孔骤缩"], "remove": ["然而"]},
    "warn":  {"add": ["闻言"], "remove": []},
    "limit": {"add": [{"pattern": "皎洁", "max": 1}], "remove": []}
  }
}
```

合并顺序：内置默认 → add 追加 → remove 剔除。`check --rules` 随时查看合并结果。
阈值同理：`gate.thresholds` 中按 key 覆盖（min_words/max_dash/max_warn/max_emotion_naming/bare_tag_max_ratio）。

## 误报处理

- 人名/书名恰含 ban 词（如角色名「林不禁」）：把角色改名，或用 limit 降级
- 「然而」在高频转折场景确需保留：remove 后建议在 G10 关注句式多样性
- 章末以对话收尾但末句是陈述句：合规（只拦 ？/！/平收）
- 疑似空章（words<10）为提示性 advisory，不阻塞 renumber --check

## 修订优先级表的使用

作者润色时间是稀缺资源，按热度排序改：

1. 先改热度最高段落（error 密集区，通常也是 AI 味最重的段落）
2. 每段参考「修改指引」列：该段命中的规则对应的改写方向
3. 改完复跑 `check N`，观察分数变化与剩余违规，直到只剩 info 或可接受的 warn

## 框架一致性校验（C01-C05，`--consistency`）

G01-G12 管的是**这一章的句子好不好**；C01-C05 管的是**这一章该不该存在**。
长篇真正的杀手不是文笔差，而是写到三十万字发现自己写了另一个故事。
这组规则把"跑偏信号"变成机检提示，不阻塞（warn/info 级），供作者复核。

| ID | 名称 | 级别 | 检查内容 |
|---|---|---|---|
| C01 | 卷目标呼应 | warn | 本章正文是否命中本卷 goal 的关键词。过渡章可忽略此提示 |
| C02 | 角色动机锚定 | warn | 出场角色是否都在框架人物网登记了 own_goal；无动机者易沦为工具人 |
| C03 | 卷内伏笔进度 | info | 本卷范围内预期回收的伏笔是否已到期未收 |
| C04 | 卷章节范围 | info | 章号是否已抵近本卷预定范围末尾（该收束了） |
| C05 | 主题触碰 | info | 本章是否对 theme.question 有所回应（命中主题词） |

输出为章节报告中的附表格。框架未建立时自动跳过（不报错）。
启发式判定（关键词命中）会有漏判，**以提醒作用为主，不是硬性判决**。

## 全书体检（W01-W04，`health` 命令）

G01-G12 管「这一章的句子好不好」，C01-C05 管「这一章该不该存在」，
W01-W04 管「**这本书有没有在悄悄地坏掉**」——单看每章都挑不出毛病，
但把它们排在一起看，趋势是危险的。

| ID | 名称 | 级别 | 检查内容 |
|---|---|---|---|
| W01 | 爽点密度与呼吸章 | warn | 连续 ≥6 章都是强钩子 → 缺呼吸章 |
| W02 | 钩子类型多样性 | warn | 单一钩子类型占比 >60% → 预期疲劳 |
| W03 | 空转风险 | info | 已写 ≥10 章但 >50% 缺 spec 推进目标 |
| W04 | 字数离群 | info | 出现字数不足均值 45% 的章 |

**为什么要有这一组**：长篇真正的淘汰赛在 30 万字之后，三种死法是「空转、水、人设崩」。
W01/W02 治「不给读者喘气」，W03 治空转，W04 治凑数。它们都是趋势判断，
所以必须**跨章**看——这也是它们独立于 G 系列的原因。

阈值常数在 `wholebook.py` 顶部（`DENSE_STREAK`、`STRONG_HOOKS`），按项目需要调整。
