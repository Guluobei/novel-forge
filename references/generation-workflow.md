# 生成引擎工作流：80 分草稿 + 作者润色

本技能的核心协作模式：**Claude 是生成引擎与调度员，作者是终审润色者**。
不追求"一键成书"，追求"每一章都在作者掌控下以最小成本达标"。

## 角色分工

| 角色 | 职责 | 不做什么 |
|---|---|---|
| Claude（生成引擎） | 写 spec → 装配上下文 → 生成 80 分草稿 → 跑门禁 → 交修订导航 | 不批量生成；不替作者做语言润色；不改作者已润色的段落 |
| 作者（终审） | 确认 spec → 润色语气/词句/节奏 → 终审通过 | 不必关心机检项（脚本已兜底） |
| 脚本（确定性层） | 上下文装配、词表扫描、字数、台账、预警 | 不做创作判断 |

## 「80 分」的定义（生成质量线）

生成草稿时，以下四项必须做到位——它们是作者无法低成本修补的结构性问题：

1. **情节推进**：spec 的 must_happen 全部发生；无注水段落
2. **人物逻辑**：行为符合角色卡动机与状态；对话严格按声线卡区分（高频词/句式/比喻域）
3. **设定一致**：遵守世界观铁律；伏笔按登记册处理（到期必收，不乱开新支线）
4. **钩子就位**：章末有明确钩子（8 类之一，参照近期历史避免连续同型）

以下部分**刻意不做满**——留给作者润色的空间：

- 语言风格不打磨到"精致"：能用平实准确的句子就不用华丽修辞
- 不堆意象、不写排比、不做主题升华（这些是 AI 味重灾区，也是作者最容易亲手改好的部分）
- 语气、口头禅、节奏的"人味"由作者定稿

> 原则：**结构问题脚本管，语言品味作者管。** 生成时守好结构，交出时留足余地。

## 标准创作循环（每章 8 步，顺序不可乱）

1. **建章**：`chapter new --title 章名`（若尚未创建）
2. **写 spec 并确认**：`chapter spec N --init` 生成骨架 → 填入 summary / must_happen / tension_curve / characters / new_hooks → **向作者展示并获确认**。spec 未经确认不得动笔
3. **装配上下文**：`context N`，通读输出（本章 spec、上一章结尾、声线卡、待回收伏笔、钩子历史）
4. **生成正文**：按下方《生成准则》写作，直接把正文写入章节文件
   - 正文格式：frontmatter 之下，首行 `# 第N章 标题`
   - 完成后更新 frontmatter：`hook_type`（8 类之一）、`words`（用 `chapter stats N` 校准）
5. **跑门禁**：`check N`
6. **交修订导航**：把报告中的「修订优先级」表交给作者——哪几段热度最高、命中什么规则、往哪个方向改。**不要自己顺手把语言改到满分**，那是作者的乐趣与权利
7. **作者润色**：作者直接编辑章节文件改语气/词句（无需任何命令）
8. **收尾**：作者确认后复跑 `check N` 确认机检项清零（或仅剩 info）→ `chapter set-status N --status done` → 有新伏笔则 `foreshadow add` 登记 → 下一章回到第 1 步

## 生成准则（写正文时遵守，而非事后补救）

机检是兜底，生成时就按以下规则写，可让草稿天然 80 分：

**情绪与动作**
- 情绪外化：`她很紧张` → `她把烟点反了两次`；禁止「感到/觉得/一股XX涌上心头」
- MRU 顺序：外部刺激 → 身体反应（0.1s）→ 反射动作 → 理性思考 → 言语行动
- 开篇从声音/动作/对话切入，禁固定顺序的场景铺陈

**对话**
- 每个角色的对话可盲测辨识（靠声线卡：高频词、句式长短、比喻域）
- 对话标签：动作标签为主（`他把杯子放到桌上。`），裸标签（他说/我说）占比 <30%
- 对话后少跟情绪注解，留潜台词

**句子与段落**
- 长短句交替：句长变异系数 ≥0.25；段首开头方式多样
- 破折号 ≤12 处/章：解释改冒号、转折改句号、补充改分号
- ban 词表内的词生成时直接不用（`check --rules` 可查看生效词表）

**比喻**
- 三原则：具体（有画面）/ 意外（跨类别连接）/ 角色化（符合 POV 认知）

**章末**
- 钩子类型从 8 类选一（危机/悬疑/反转/信息/情感/时间/选择/生存）
- 禁反问、禁感叹、禁「第X章完」平收；以陈述、动作或画面收

## 交互铁律

1. **一次一章**：禁止未经作者要求连续生成多章
2. **spec 先行**：未确认 spec 不动笔；作者说"随便写"时给出 2-3 个 spec 方案供选择
3. **check 必跑**：交付草稿前必跑 `check N` 并附修订导航；不跑 = 未完成
4. **不越界润色**：作者已改过的段落，除非作者明确要求，不做二次改写
5. **机检兜底**：作者说"检查一下"时跑 `check`；说"哪里 AI 味重"时展示修订优先级表
6. **状态同步**：章节状态流转 draft → writing → review → done，用 `set-status` 维护，供进度统计

## 插章与长篇维护

- 需要在第 N 章前补写：`chapter insert --before N --title 章名 --dry-run` 预览 → 确认执行 →
  章号自动重排、伏笔章号自动 +1、spec 伴生文件同步迁移
- 伏笔预警：`foreshadow audit`；到期未回收会标 overdue，超期 3 章升级 severe
- 每完成一批章节，建议让作者看 `stats` 与 `progress` 把控节奏
